# Issue Decomposition

Decompose an approved PRD into independently valuable and verifiable slices. Avoid creating only horizontal issues such as “database,” “API,” and “UI” when a vertical slice is feasible.

For every proposed issue include repository, PRD ID, requirement IDs, acceptance criteria, scope, dependencies, validation, migration, documentation, and operational implications. Check for orphaned requirements, missing failure paths, oversized issues, unapproved scope, and dependency cycles.

Present the complete plan for approval before issue creation.
