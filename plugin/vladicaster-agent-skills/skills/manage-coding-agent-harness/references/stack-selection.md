# Stack Selection

Recommend technology only to establish an effective engineering baseline and harness.

1. Identify required quality attributes and hard constraints.
2. Select the simplest viable system shape.
3. Reuse demonstrated team expertise when it satisfies requirements.
4. Select data, hosting, identity, integration, UI, testing, and telemetry technologies.
5. Add optional infrastructure only when a concrete requirement justifies its cost.

For each choice, state the requirement satisfied, operational complexity, team fit, security fit, portability, maturity, expected cost, and trigger for reconsideration.

Prefer one recommendation. Offer one alternative only when it represents a meaningful tradeoff. Do not recommend microservices, Kubernetes, messaging, caching, search, vector storage, or multiple databases merely as future-proofing.
